## 2. 长视频脚本：15 分钟精修版

### 00:00-00:50 开场：研究者的真实入口

画面：

- 使用 `01_home_sidebar_demo.png` 或直接打开首页。
- 左侧栏展开 `π-zaya Demo`。
- 鼠标缓慢扫过 6 个演示会话标题。

旁白：

> 做文献调研时，真正耗时间的往往不是“找一篇论文”，而是反复确认：这个说法来自哪篇文章？原文在哪里？它和我的 related work 到底有什么关系？Pi_zaya 想解决的是这个闭环：从 PDF 文献库提问，到答案、引用、原文核查、研究摘录和引用导出，全部在一个工作台里完成。

屏幕字幕：

```text
从 PDF 文献库提问，到可追溯证据
```

### 00:50-02:00 文献库：先证明这不是空壳 demo

画面：

- 打开 `文献管理`。
- 使用 `21_library_overview.png` 和 `22_library_list_status.png` 作为补拍参考。
- 展示 21 篇文献、转换状态、质量分、可问答状态。

旁白：

> 这里已经有一批真实论文。每篇 PDF 会经过转换、质量检查、分块和索引。广告里我们不从一个孤立聊天框开始，而是先看到文献库本身：哪些文件已经转换，哪些可以被问答系统使用，质量状态是否正常。这一步对学术工具很重要，因为答案质量最终取决于源材料有没有被正确处理。

屏幕字幕：

```text
PDF → Markdown → 分块 → 索引 → 可问答
```

### 02:00-03:20 全库提问：用真实研究问题启动

画面：

- 切到 `全库检索：单光子成像的噪声建模`。
- 如果重拍，从输入框输入主问题。
- 使用 `02_full_library_question_ready.png` 作为构图参考。

旁白：

> 现在我们问一个真实的研究问题：单光子成像为什么需要专门建模噪声？有哪些代表性做法？这个问题不是让系统复述某篇论文摘要，而是要求它跨文献寻找相关机制、方法和参考来源。

屏幕字幕：

```text
直接问整个文献库
```

### 03:20-04:35 检索与生成：保留工作过程

画面：

- 点击发送。
- 保留检索和生成状态，不要马上剪掉。
- 使用 `03_generation_started.png` 作为参考。

旁白：

> 生成时可以短暂停留一下。这里的重点不是“聊天机器人正在打字”，而是系统正在把自然语言问题转成文献检索任务，再把相关片段组织成回答。对研究场景来说，这比一个没有来源的漂亮答案更重要。

屏幕字幕：

```text
检索相关论文片段，并生成可追溯回答
```

### 04:35-05:45 答案与相关文献：第一层可信度

画面：

- 展示回答完成后的页面。
- 镜头停在答案和 `可能相关的参考文献`。
- 使用 `04_full_library_answer_refs.png`。

旁白：

> 答案下方会出现可能相关的参考文献。这一步把“回答”和“文献”放回同一个画面。研究者不需要先相信答案，而是可以沿着文献卡继续检查来源。

屏幕字幕：

```text
答案不是终点，文献来源就在旁边
```

### 05:45-07:00 引用定位：页码、DOI、指标与操作入口

画面：

- 展开 `参考定位`。
- 滚动到参考文献卡。
- 使用 `05_reference_locate_expanded.png` 和 `06_reference_cards_visible.png`。

旁白：

> 这里可以看到页码、DOI、期刊指标、JCR 信息，以及定位、PDF、引用和阅读按钮。广告镜头要在这里停够久，因为这是 Pi_zaya 和普通问答界面的核心差异：它不只给答案，还把后续核查动作做成了界面的一部分。

屏幕字幕：

```text
页码 / DOI / IF / JCR / 原文入口
```

### 07:00-08:05 从全库发现到单篇精读

画面：

- 点击第一张文献卡的 `阅读`。
- 进入 `阅读指导：Physics-informed single-photon imaging`。
- 使用 `08_reading_guide_empty.png`。

旁白：

> 当一篇论文变得重要，就可以直接进入阅读指导。这里有一个关键控制：本文和全库。全库适合找线索，本文适合做精读和证据核查。这个切换让研究过程从“广泛探索”自然进入“单篇确认”。

屏幕字幕：

```text
全库找线索，本文做精读
```

### 08:05-09:15 本文追问：要求系统给出证据

画面：

- 切换到 `本文`。
- 输入追问并发送。
- 使用 `09_reading_guide_question_ready.png`、`10_reading_guide_generation_started.png` 和 `11_reading_guide_answer.png`。

旁白：

> 接下来不是问“总结这篇论文”，而是问它为什么和刚才的问题相关，并要求用三点说明，给出对应的原文依据。这个问题会迫使系统把跨库发现和单篇证据连接起来。

屏幕字幕：

```text
追问：为什么相关？证据在哪里？
```

### 09:15-10:35 单页 Reader：原文核查与阅读功能

画面：

- 点击答案里的 `原文`，随后切换到单页 Reader。
- 展示干净的正文高亮证据，不滚到 Figure 7 图内标注文字区域。
- 点击 `章节`，显示左侧章节目录；点击 `证据`，回到当前高亮。
- 点击正文里的引用号，例如 `[38]`，展示文内引用卡。
- 使用 `41_clean_reader_preview.png`、`42_reader_chapter_feature.png`、`44_reader_reference_feature.png`。

旁白：

> 点击原文之后，不使用右侧抽屉，而是切到单页 Reader。这样画面更完整，也更适合广告录屏。这里要展示三件事：第一，答案能回到原文高亮；第二，章节目录可以快速跳转；第三，正文里的引用号可以继续展开成文献卡。Reader 不是普通 PDF 预览，而是能把阅读、定位和引用关系接起来的工作区。

屏幕字幕：

```text
原文定位 / 章节导航 / 文内引用卡
```

### 10:35-11:35 文内引用卡：沿着引用继续扩展

画面：

- 打开独立 Reader。
- 点击文内 `[R1]`。
- 使用 `15_standalone_reader_page.png` 和 `16_reader_inpaper_reference_card.png`。

旁白：

> 阅读过程中遇到文内引用，也可以继续展开参考文献卡。它不是一个静态 PDF 阅读器，而是把论文正文、引用关系和文献信息接在一起。对 related work 写作来说，这一步能把“读到一条线索”变成“收藏一条候选文献”。

屏幕字幕：

```text
文内引用，也能展开成可收藏文献
```

### 11:35-13:35 研究摘录篮：多篇文献、详情展开与 DOI

画面：

- 从 Reader 文内引用卡点击 `加入研究摘录篮`，回到聊天页打开 `研究摘录篮`。
- 展示项目级摘录篮中已有 4 条文献，至少包括：
  - `Single-photon avalanche diode imagers in biophotonics: review and outlook`
  - `First-Photon Imaging`
  - `Wide-field, high-resolution Fourier ptychographic microscopy`
  - `Characterization-based modeling of retriggering and afterpulsing for passively quenched CMOS SPADs`
- 点击第一条文献卡展开详情，停留在摘要/摘录、质量状态、来源路径、DOI 链接。
- 鼠标移到 DOI 链接上，展示它是可点击外链；不要真的跳走，除非补拍 DOI 打开页。
- 点击同一条文献卡收拢详情。
- 再展开第二条文献卡，展示不同 DOI、不同来源位置和不同用途标签。
- 使用 `19_chat_tab_reopened.png`、`42_reader_chapter_feature.png`、`44_reader_reference_feature.png`，并补拍新的多条摘录篮画面。

旁白：

> 研究摘录篮不是一个简单收藏夹。它更像 related work 的临时工作台：从 Reader 里遇到的上游引用、从问答里推荐的相关论文，都可以沉淀到这里。每条文献可以展开，看到摘要、摘录、来源路径、质量提示和 DOI。这里要故意展开一条、收拢一条，再展开另一条，让观众看到它不是静态列表，而是可以检查、筛选、组织的文献素材。

屏幕字幕：

```text
多篇入篮 / 展开详情 / DOI 可点击
```

### 13:35-14:25 导出引用：选中、可见、全部

画面：

- 勾选 2 条文献，展示 `已选中` 状态。
- 点击 `导出引用`。
- 依次切换导出范围：`选中`、`可见`、`全部`。
- 展示下载按钮：`BibTeX`、`RIS`、`Markdown`。
- 展示复制按钮：`复制 BibTeX`、`复制 GB/T`、`复制 Markdown`，以及 `CSV 数据表`。
- 如有导出预检提示，展示“元数据完整 / DOI ready / 可导出”的健康状态。

旁白：

> 收集之后，下一步就是写作。这里可以只导出选中的两篇，也可以导出当前筛选可见的文献，或者导出整个篮子。格式也不是只有 BibTeX，还包括 RIS、Markdown、GB/T 和 CSV。对于论文写作来说，这一步把阅读现场直接接到文献管理和草稿写作。

屏幕字幕：

```text
选中 / 可见 / 全部，按写作场景导出
```

### 14:25-15:00 收束：完整闭环

画面：

- 快速回看左侧项目、文献库、Reader、导出面板。
- 结束在首页或引用导出面板。

旁白：

> 这条演示线从一个真实问题开始：问整个文献库，拿到带来源的回答；发现重要论文后进入单篇阅读；用 Reader 核查原文；沿着文内引用扩展相关文献；在研究摘录篮里检查 DOI 和来源；最后按选中、可见或全部导出引用。Pi_zaya 的核心不是替你跳过阅读，而是把阅读、核查、整理和写作准备变成一个连续的研究流程。

屏幕字幕：

```text
问 → 查 → 读 → 收集 → 导出
```

## 5. 补拍清单

优先补拍这些动态镜头：

| 优先级 | 镜头 | 原因 |
|---:|---|---|
| 1 | 输入主问题并发送 | 静态截图不如真实输入有代入感 |
| 2 | 答案逐步生成 | 能表现检索和生成过程 |
| 3 | 展开参考定位 | 是可信度核心动作 |
| 4 | 点击 `阅读` 进入阅读指导 | 串起全库和单篇精读 |
| 5 | 点击 `原文` 打开 Reader | 长短视频都需要 |
| 6 | 点击 `[R1]` 展开文献卡 | 展示交叉引用能力 |
| 7 | 加入研究摘录篮并导出 | 形成结尾闭环 |

不建议在广告正片里展开：

- API key 设置
- 上传 PDF 的后台等待过程
- 转换修复的细节日志
- 旧测试会话或无关项目
- Streamlit 或旧入口相关内容
