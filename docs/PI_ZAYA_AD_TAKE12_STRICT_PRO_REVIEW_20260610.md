## 总结论

Take12 不建议发布，也不建议在此基础上小修补。它需要重录。

原因不是单一的清晰度或声音问题，而是“产品演示状态”和“广告叙事”同时失控：画面中出现重复研究路径、空文献篮、导出段没有导出动作、写作段没有文献篮上下文；同时存在大量静止画面，字幕和旁白仍在推进，导致观众会觉得视频在“讲一个比画面更强的产品”，可信度下降。

可保留的素材方向：

- π-zaya 正版 logo 片头可以保留，但必须缩短。
- 文献库 Q100、21/21、筛选和分类卡片有展示价值。
- Reader 中公式、表格、图片、参考文献的转换质量值得作为核心卖点。
- 引用卡、原文定位、文献篮、导出、写作上下文这些功能仍然是正确故事线，但必须用真实点击和真实状态展示。

不可保留的现有段落：

- 04:06-04:41 结构化回答段中的重复研究路径。
- 05:53-07:04 文献篮与导出段，因为画面显示空篮。
- 07:04-07:31 写作段，因为画面仍是全库范围，不是文献篮上下文。
- 任何超过 5 秒没有画面变化、却仍由旁白推进产品能力的镜头。

## 技术审查

当前 release 版本参数：

- 分辨率：1280×880
- 编码：H.264 High, yuv420p
- 帧率：30 fps
- 时长：472 秒，即 7 分 52 秒
- 视频码率：约 0.6 Mbps
- 总码率：约 0.7 Mbps

这个码率对密集 UI 录屏偏低。即使源画面有 2x 截图，最终播放时经过播放器缩放，中文小字会发糊，细线和文字边缘容易出现“重影感”。

音频检测：

- 平均音量：-25.5 dB
- 峰值：-0.5 dB

这说明旁白整体偏小，但峰值接近削顶。听感会出现“底噪明显、声音薄、某些音节刺”的问题。当前 Windows TTS 声音也不适合作为发布级广告旁白。

静止画面检测显示大量超过 5 秒的 freeze：

- 00:02-00:09：片头静止
- 00:12-00:19：片头静止
- 00:47-01:01：文献库静止 13.5 秒
- 01:22-01:32：质量中心静止 10.3 秒
- 01:48-02:00：Reader 顶部静止 12.3 秒
- 04:24-04:41：回答段静止 16.8 秒
- 06:02-06:14：文献篮段静止 11.3 秒
- 06:14-06:28：文献篮段继续静止 14.2 秒
- 06:50-07:06：导出/写作过渡静止 16.2 秒
- 07:18-07:31：写作段静止 12.8 秒

结论：用户指出的“很长时间停留在同一个页面”是客观存在的。广告版每 3-5 秒必须有可见变化：点击、展开、滚动、选中、计数变化、定位跳转、局部放大或镜头切换。

## 用户指出的六个问题逐项判定

### 1. 研究路径三条问题重复

判定：严重问题，必须修复。

在 04:20 关键帧中，Q1、Q2、Q3 都是“单光子成像为什么需要专门建模噪声？有哪些代表性做法？”。这个镜头不应出现在广告里。

重录要求：

- 如果展示研究路径，必须准备三条不同节点：
  - Q1：单光子成像为什么需要专门建模噪声？
  - Q2：不同噪声会影响哪些重建方法和评价指标？
  - Q3：哪些论文适合作为 related work 的核心引用？
- 每条节点都要有不同标题、不同回答状态、不同点击结果。
- 录制脚本必须加入断言：可见研究路径文本去重后数量至少为 3，否则停止录制。

### 2. 段落之间不流畅，有长留白

判定：严重问题，必须重剪并重录。

当前视频多处 10 秒以上画面静止。广告中可以有停顿，但停顿必须服务理解；现在的停顿多是页面没有变化、旁白在继续讲，观众会感觉画面跟不上声音。

重录要求：

- 单个静态镜头最长 2.5 秒，标题卡最长 6-8 秒。
- 每段结尾必须用动作衔接下一段：例如“点击打开 Reader”接 Reader，“点击入篮”接文献篮，“点击导出”接导出面板。
- 不再用长时间停留来填满旁白，旁白长度反过来服从画面动作。

### 3. 字幕和语音内容与画面不对

判定：严重问题，必须以镜头为单位重写文案。

当前有多处字幕在讲抽象能力，但画面没有对应动作：

- 结构化回答段讲“每个判断带来源标记”，右侧却显示重复研究路径。
- 文献篮段讲“勾选其中几篇”，画面显示空篮。
- 导出段讲 BibTeX/RIS/GB/T/CSV，画面没有出现导出面板。
- 写作段讲“文献篮作为上下文”，画面仍是全库。

重录要求：

- 每句旁白必须能在同一镜头中找到对应画面证据。
- 字幕不再解释未出现的功能。
- 如果某功能录制失败，脚本自动跳过旁白或停止生成，不能让字幕硬讲。

### 4. 文献篮为空

判定：发布级硬伤，必须整段重录。

文献篮是 π-zaya 的关键差异点之一，但当前广告中反而展示了“已收藏 0 条”。这会让观众以为该功能不可用。

重录要求：

- 不直接依赖后端 seed 状态，必须在画面上真实点击加入。
- 至少加入 3 篇：
  - NatCommun-2023 High-resolution single-photon imaging...
  - First-Photon Imaging
  - Single-photon avalanche diode imagers in biophotonics...
- 每次点击后都要看到计数变化或条目增加。
- 文献篮段开始前脚本必须断言：右侧条目数 >= 3，且页面不能出现“还没有收集文献”。

### 5. 旁白太 AI，杂音大

判定：不适合作为发布版。

当前旁白有几个问题：

- 声音像系统 TTS，缺少广告需要的自然呼吸和强调。
- 平均音量过低，峰值接近 0 dB，导致听感不稳。
- 文案句式重复，“不是……而是……”“重点不是……”出现太多，听起来像说明稿，不像广告。
- 之前还出现过操作指令混入语音的问题，这类内容必须在音频生成前彻底隔离。

重录要求：

- 优先使用真人旁白。
- 如果使用 TTS，必须换成自然度更高的神经网络声音，不能使用 Windows System.Speech。
- 音频处理标准：
  - loudness：-16 LUFS 左右
  - true peak：不高于 -1.5 dB
  - 去噪、轻压缩、去齿音
- TTS 输入文件只允许包含广告旁白，不允许包含录制指令、镜头提示、等待时间。

### 6. 画面不够清晰

判定：需要重新定义交付规格。

当前 1280×880 版本码率偏低，UI 又是高密度文字界面，播放器缩放后容易糊。之前的 2560×1760 yuv444p master 虽然分辨率高，但 Windows Photos 不支持，不适合作为交付版。

重录要求：

- 录制源：浏览器内容区用 1280×800 或 1440×900 CSS viewport，deviceScaleFactor 至少 2。
- 发布版：输出 1920×1200 或 1920×1080 的 yuv420p H.264，避免 yuv444p。
- 码率：不要再低于 0.6 Mbps；UI 广告建议 8-16 Mbps 区间，或 CRF 8-12 并验证实际清晰度。
- 密集文字不要靠全屏硬看，重要区域用局部放大或重新构图。
- 鼠标点击位置必须准确，点击时用真实 cursor/click ring，不能用偏移的后期框线。

## 项目功能展示取舍

### 应该加强展示

- Reader 转换质量：选择一篇转换效果最好的论文，从标题、摘要、公式、表格、图片、参考文献快速过一遍。
- 引用可追溯：点击答案引用标记，打开文献卡，再进入 Reader 原文位置。
- 文献篮：真实加入多篇，展示计数、条目、勾选、作为下一轮提问范围。
- 导出：真实打开导出面板，展示至少三种格式，复制一个格式。
- 写作闭环：用“已选文献/文献篮范围”生成 related work 提纲，而不是全库。
- 质量中心：展示转换质量不是黑箱，但只要短而清楚。

### 应该减少展示

- 片头 logo 静止。
- 长时间滚动 Reader。
- 长时间停在聊天答案正文。
- 反复展示同一个 single-photon 问题。
- 抽象口号式文案。

### 不应该出现在广告里

- 重复研究路径。
- 空文献篮。
- 禁用按钮、空状态、placeholder 被当成功能演示。
- “Take11/Take12”这类制作内部字样。
- Debug、fallback、本地测试状态文字。
- 画面没有出现的功能，却由旁白/字幕声称已经发生。

## 建议的新主广告结构

我不建议继续把主广告做成 15 分钟。15 分钟适合“完整教程版”，不适合广告。主广告建议 5-6 分钟，节奏更密，每个功能都要有真实动作。

## 如果必须做 15 分钟版本

15 分钟版本应该叫“完整演示”或“深度工作流”，不要当作主广告。它必须比 5 分钟版多真实内容，而不是把同一页面停更久。

可扩展内容：

- 上传/批量转换一篇新 PDF，并展示进入队列。
- 质量中心解释 Q100、待处理、修复推荐。
- Reader 从头到尾过一篇转换质量最好的论文，但每 20-30 秒必须有明确章节目标。
- 研究路径展示 3-5 个真实问题分支，每个分支问题必须不同。
- 文献篮展示增删、勾选、清空、按已选范围提问。
- 导出展示 BibTeX、GB/T、Markdown 三种结果。
- 复制 Markdown 到写作草稿，形成 related work 段落骨架。

15 分钟版验收标准：

- 任何静止画面不得超过 4 秒，除非正在阅读明确高亮内容。
- 任何旁白句子都必须对应当前画面。
- 每 60 秒至少展示一个新的功能动作或结果。
- 不允许出现空状态冒充完成态。

## 旁白文案风格修正

当前文案太像 AI 说明稿，主要问题是抽象、对称句式多、缺少用户处境。

应避免：

- “它不是……而是……”
- “重点不是……而是……”
- “对科研工具来说……”
- “完整走一遍”

建议改成更自然的广告口吻：

- “找文献时，真正耗时间的不是问一句，而是确认答案从哪里来。”
- “π-zaya 先把本地 PDF 整理成可检查的文献库。”
- “点开答案里的引用，可以一路回到 DOI、原文段落和图表。”
- “确认过的论文放进文献篮，下一轮问题就只围绕这些材料展开。”
- “最后直接导出 BibTeX、GB/T 或 Markdown，把阅读结果带进写作。”

字幕原则：

- 中英字幕放在底部白条是可行的，但每条字幕只写当前画面正在发生的动作。
- 中文一行优先，英文一行辅助，不要把一整段旁白全部塞进字幕。
- 字幕不得遮挡输入框、引用卡、文献篮条目、导出格式按钮。
- 字幕与语音必须来自同一份 clean script，不允许后期分开改。

## 重录前验收闸门

录制脚本必须在关键段落加入 fail-fast 检查：

```text
研究路径：
- 可见节点数 >= 3
- 节点文本去重后数量 >= 3
- 不允许 Q1/Q2/Q3 文本完全一致

文献篮：
- 进入文献篮段前，可见条目数 >= 3
- 不允许出现“已收藏 0 条”
- 不允许出现“还没有收集文献”

导出：
- 导出面板必须可见
- BibTeX、RIS、Markdown、GB/T、CSV 至少出现 3 个
- 至少真实点击一次复制/切换

写作：
- 提问范围必须显示为文献篮、已选文献或等价状态
- 不允许仍显示“全库”却说“基于文献篮”

画面：
- 每个镜头最长静止 2.5 秒
- 鼠标点击位置必须落在真实按钮中心
- 不再使用歪斜的大框线标注

音频：
- TTS 输入只包含广告旁白
- 无录制指令、等待指令、镜头备注
- loudness 约 -16 LUFS，true peak <= -1.5 dB
```
