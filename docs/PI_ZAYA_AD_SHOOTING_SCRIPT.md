## Take8 执行基准

当前正式制作请优先使用：

`docs/PI_ZAYA_AD_TAKE8_PRODUCTION_SCRIPT_20260610.md`

这个 Take8 脚本已经把审查发现、补拍功能、遮挡修正、`1280x800` 画幅、Reader 单页形式、文献篮高级流程、范围切换和写作提纲结尾落实成镜头级执行清单。

本文件保留为原始广告计划和素材清单；正式录制与剪辑以 Take8 制作脚本为准。禁止使用旧 Streamlit 入口。

Take8 的故事线改为：

1. 研究任务出现：说明要写 related work，需要发现、核查、引用。
2. PDF 入库：展示 Library、上传、转换、索引、可问答状态。
3. 质量中心：展示转换质量、修复建议和修复结果，避免把坏 OCR 内容当成卖点。
4. Library 管理：展示搜索、分类、标签、元数据和引用同步。
5. 全库提问：从整个文献库发现候选证据。
6. 引用卡片：打开参考、看证据焦点、DOI、IF/JCR、BibTeX、GB/T。
7. 范围切换：用全库、本文、文献篮分别完成发现、核查、综合。
8. Reader 单页：定位原文、切换证据、选中文本、高亮、追问、加入文献篮。
9. 文献篮：展示多来源加入、计数变化、标签、筛选、快照、恢复。
10. 导出预检：展示导出范围、引用格式和元数据检查。
11. 写作提纲：只基于文献篮生成 related work 提纲，并保留对应引用。
12. 结尾：回到 `π-zaya` 品牌和“可问、可查、可引用”的定位。

旧版 15-18 分钟结构可以继续作为素材池，但 Take8 长版建议放宽到 `22-25 min`，以完整展示产品的研究工作流。

## 核心定位

π-zaya 不是“单篇 PDF 聊天工具”，而是一个完整的学术文献研究工作台。

主线应该是：

> 文献入库 -> 自动命名与转换 -> Library 分类和标签管理 -> 全库找证据回答 -> 参考定位进入阅读指导 -> Reader 原文核查 -> 文内交叉引用追踪 -> 文献篮整理 -> 一键导出 Cite。

广告最重要的卖点顺序：

1. **全库问答**：不局限当前论文，可以从整个文献库找相关证据。
2. **参考定位与 Reader**：答案不是孤立文本，可以回到原文和上下文。
3. **Library 入库与整理**：PDF 可自动命名、转换、分类、打标签并进入知识库。
4. **文献篮与 Cite 导出**：把证据和文献收起来，一键导出 BibTeX / RIS / Markdown / GB/T。
5. **文内参考追踪**：Reader 里的交叉引用可以直接点开看卡片。

首页短定位：

> π-zaya  
> 您的学术文献助理

广告核心句：

> 从文献库找答案，回到原文看依据。

## 演示素材设计

### 主角文献

优先使用：

`NatCommun-2023-High-resolution single-photon imaging with physics-informed deep learning.pdf`

理由：

- 标题专业，适合展示科研场景。
- 适合讲“单光子成像、物理噪声建模、物理先验、深度学习增强”。
- 可以自然出现在全库参考定位中，再进入阅读指导。
- 适合展示 Reader 原文定位、正文交叉引用、参考文献卡片和文献篮。

### 配角文献

Library 中最好准备一组同主题或邻近主题文献，覆盖：

- single-photon imaging
- SPAD noise / detector noise
- computational imaging
- single-pixel imaging
- compressive imaging
- physics-informed deep learning
- NeRF / 3D reconstruction

如果库里实际文献方向不完全一致，就用“计算成像 / 物理模型 / 深度学习增强 / 3D 重建”作为统一主题。

### Library 展示准备

录屏前建议准备一个演示项目，避免露出私人会话。

Library 中最好有：

- 20 篇以上文献，形成“真实文献库”的观感。
- 至少 1 篇新导入 PDF，用来展示自动命名和转换。
- 多篇已转换、可问答的文献。
- 至少 3 个分类，例如 `Single-photon imaging`、`Computational imaging`、`3D reconstruction`。
- 至少 6 个标签，例如 `SPAD`、`noise model`、`physics-informed`、`deep learning`、`NeRF`、`single-pixel`。
- 至少 1 篇文献展示系统建议分类/标签。
- 文献篮录制前尽量保持干净，方便从广告流程里现场加入条目。

## 拍摄安全

不要拍到：

- API key
- `.env`
- 本地隐私路径
- 私人聊天内容
- 不适合公开的大段论文全文

可以拍：

- 文献标题
- Library 列表、分类、标签、状态
- 自动命名建议
- 转换和入库状态
- 回答摘要
- 小范围原文定位上下文
- 参考文献卡片
- 文献篮和引用导出界面

慢的地方可以倍速：

- PDF 转换
- 知识库更新
- 引用同步
- LLM 回答生成

关键交互建议正常速度：

- 切换到“全库”
- 点击参考定位卡片
- 进入阅读指导
- 打开侧边 Reader
- 点击“单独页打开”
- 点击 Reader 里的交叉引用
- 加入文献篮
- 一键导出 Cite

## 长版视频脚本（15-18 分钟）

这版目标是“功能展示完整”，适合 B 站、官网、GitHub README、给老师/同学/潜在用户看。

### 0. 开场：产品定位（0:00-0:35）

画面：

- 首页空状态。
- Logo 旋转和副标题打字动画。
- 停在 `π-zaya / 您的学术文献助理`。

旁白：

> π-zaya 不是只对一篇 PDF 聊天。它会把你的本地文献整理成知识库，让你从整个文献库中找答案，并回到原文核查依据。

字幕：

> 从文献库找答案，回到原文看依据。

### 1. Library 扫场：这是一个文献库，不是一篇 PDF（0:35-1:50）

画面：

- 点击侧栏“文献管理”。
- 快速扫过大量文献列表。
- 展示已转换、可问答、待处理、质量状态。
- 展示分类视图、标签视图、阅读状态或元数据。

动作：

1. 在文献列表中滚动 5-8 秒。
2. 切到分类视图，展示多个分类。
3. 切到标签视图，展示多个标签。
4. 点开一篇文献元数据，展示分类、标签、阅读状态、备注。

旁白：

> 研究不是从提问才开始。π-zaya 首先帮你把 PDF 变成一个可管理、可检索、可维护的文献库。

字幕：

> Library：批量管理文献、分类、标签和入库状态。

### 2. 文献入库：自动命名、转换、更新知识库（1:50-3:20）

画面：

- 上传或选择一个 PDF。
- 展示自动命名建议，例如期刊-年份-标题格式。
- 展示保存/入队/转换状态。
- 展示更新知识库或可问答状态。
- 可短暂展示引用同步、转换质量或文库维护状态。

动作：

1. 选择一个新 PDF 或展示待处理 PDF。
2. 展示自动命名建议和应用命名。
3. 展示转换队列或转换完成。
4. 展示“更新知识库”或文献进入可问答状态。

旁白：

> 新文献入库时，π-zaya 可以根据元数据生成更规范的文件名，再转换成 Markdown 和索引，让 PDF 真正进入可问答的知识库。

字幕：

> 自动命名 -> PDF 转 Markdown -> 更新索引 -> 可问答

倍速建议：

- 转换和更新知识库 4x-8x。
- 自动命名建议和应用命名正常速度。

### 3. 主功能：普通模式直接问全库问题（3:20-5:20）

画面：

- 回到对话页。
- 保持普通对话模式。
- 范围切换到“全库”。
- 输入一个研究问题。
- 回答中出现多篇文献和参考定位卡片。

主问题：

```text
单光子成像为什么需要专门建模噪声？有哪些代表性做法？
```

动作：

1. 切换范围到“全库”。
2. 输入问题。
3. 回答生成过程可倍速。
4. 回答完成后，停留在多篇文献证据和参考定位卡片。
5. 重点让主角论文出现在参考定位中。

旁白：

> 这是 π-zaya 的核心能力：你不需要先指定某一篇论文，也不需要在问题里刻意说“从库里找”。像平时做研究一样直接提问，它会从整个文献库中找相关文献和证据。

字幕：

> 全库找证据，不局限当前文章。

### 4. 从参考定位进入阅读指导（5:20-6:40）

画面：

- 在参考定位中找到主角论文卡片。
- 展示卡片标题、来源、相关性、摘要或依据。
- 点击“阅读 / 阅读指导 / 打开”进入这篇论文的阅读指导模式。

动作：

1. 在全库回答的参考定位区找到：
   `High-resolution single-photon imaging with physics-informed deep learning`
2. 点击卡片中的阅读入口。
3. 进入阅读指导会话。
4. 展示当前会话已围绕这篇文献展开。

旁白：

> 全库回答找到相关论文后，可以从参考定位直接进入这篇文献的阅读指导。这样流程是自然的：先从问题找到文献，再围绕关键文献精读。

字幕：

> 从全库答案，进入单篇阅读指导。

### 5. 阅读指导：围绕目标论文精读（6:40-8:00）

提问：

```text
这篇论文为什么和刚才的问题相关？请解释它如何处理物理噪声建模和物理先验，并指出对应的原文依据。
```

画面：

- 阅读指导回答。
- 回答中出现证据入口、原文按钮或参考定位。

旁白：

> 进入阅读指导后，π-zaya 会把问题收束到这篇论文本身，帮助你理解它为什么相关，以及关键依据在哪里。

字幕：

> 阅读指导：从相关文献进入深读。

倍速建议：

- 生成过程 2x-4x。
- 证据展示正常速度。

### 6. 侧边 Reader：点击证据直接定位（8:00-9:00）

画面：

- 点击回答中的“原文 / 定位 / 证据”。
- 侧边 Reader 打开。
- Reader 跳到对应原文段落。
- 展示高亮、页码、章节或上下文。

动作：

1. 点击一条证据。
2. 让侧边 Reader 打开。
3. 在定位处停留 5-8 秒。
4. 轻微上下滚动，展示上下文。

旁白：

> 回答不是停留在生成文本里。你可以直接打开 Reader，回到论文原文位置核查。

字幕：

> 回答可以回到原文。

### 7. Reader 独立页：从侧边定位到完整阅读（9:00-9:45）

画面：

- 在侧边 Reader 中点击“单独页打开”或对应图标。
- Reader 独立页打开。
- 展示更宽的阅读区、章节、证据导航或定位段落。

动作：

1. 从侧边 Reader 点击单独页打开。
2. 切到独立 Reader 页面。
3. 展示标题、章节、定位段落。
4. 返回主聊天页。

旁白：

> 快速核查可以在侧边完成；需要深入阅读时，也可以单独打开完整 Reader。

字幕：

> 侧边定位，独立页精读。

### 8. Reader 文内交叉引用：点击引用看卡片（9:45-11:00）

画面：

- 在 Reader 中找到正文交叉引用，例如 `[23]` 或作者年份引用。
- 点击交叉引用。
- 弹出参考文献卡片。
- 展示标题、作者、来源、DOI、摘要、可信信息。
- 如果支持，展示加入文献篮或打开定位入口。

动作：

1. 找到正文引用位置。
2. 点击文内引用。
3. 展示弹出的参考文献卡片。
4. 卡片停留 5-8 秒。
5. 可以加入文献篮或展示“打开原文/定位”入口。

旁白：

> 读论文时，正文里的引用经常是下一步线索。π-zaya 可以把这些交叉引用直接变成可查看的卡片。

字幕：

> 文内引用也能继续追。

### 9. 回到全库：把相关文献整理成阅读路径（11:00-12:20）

画面：

- 回到刚才的全库会话。
- 追问阅读路径。
- 回答中给出先读哪篇、再读哪篇、每篇看什么。

提问：

```text
把刚才找到的相关文献整理成一个阅读路径：先读哪篇、再读哪篇，每篇重点看什么？
```

旁白：

> 找到文献之后，π-zaya 还能把多个相关研究整理成阅读路线，帮助你决定下一步读什么。

字幕：

> 从答案变成研究路径。

### 10. 文献篮：收藏证据和文献线索（12:20-13:50）

画面：

- 打开研究侧栏 / 文献篮。
- 从回答卡片、Reader 选中文本或参考卡片加入文献篮。
- 展示文献篮条目。
- 展示搜索、排序、筛选、标签、分组。
- 展示保存本机快照。

动作：

1. 把主角论文加入文献篮。
2. 把 Reader 中的关键原文选段加入文献篮。
3. 把一个文内交叉引用卡片加入文献篮。
4. 打开文献篮，展示条目。
5. 切换按标签、来源或类型筛选。
6. 点击保存快照。

旁白：

> 真正有用的文献和证据，可以放进文献篮。它不是临时收藏，而是写作前的研究摘录区。

字幕：

> 文献篮：收藏证据，整理线索。

### 11. 一键导出 Cite：从阅读到写作（13:50-14:50）

画面：

- 在文献篮中打开“导出引用”。
- 展示当前筛选和全部范围。
- 展示 BibTeX、RIS、Markdown、GB/T、CSV。
- 点击复制或导出。

动作：

1. 打开“导出引用”。
2. 切换 BibTeX / RIS / Markdown / GB/T。
3. 展示元数据预检。
4. 点击复制 BibTeX 或导出引用。

旁白：

> 当你开始写作时，文献篮可以一键导出 Cite，连接 Zotero、EndNote 或 Markdown 写作流程。

字幕：

> 一键导出 BibTeX / RIS / Markdown / GB/T。

### 12. 可选：数据保护和版本更新（14:50-15:30）

画面：

- 打开设置页。
- 只展示普通状态：API 可用性、数据保护、版本更新。
- 不打开 API key 输入框。
- 高级维护工具只扫过标题，不展开敏感细节。

旁白：

> 对长期使用的本地文献库，π-zaya 也提供数据保护、备份和版本更新提醒。

字幕：

> 本地优先，也要可维护。

### 13. 收尾（15:30-16:00）

画面：

- 回到首页。
- 停在 `π-zaya / 您的学术文献助理`。

旁白：

> 从文献入库、全库问答，到 Reader 核查、交叉引用追踪、文献篮和 Cite 导出，π-zaya 帮你完成一条完整的研究链路。

结尾字幕：

> π-zaya  
> 您的学术文献助理  
> 从文献库找答案，回到原文看依据。

## 还可以呈现的细节功能

这些功能不一定每个都展开讲，但可以在长版里用 2-5 秒扫过，增加“这是成熟产品”的感觉。

### Library 细节

- 自动命名建议：展示从原始 PDF 文件名变成 `期刊-年份-标题` 的过程。
- 文献分类和标签：展示分类、标签、阅读状态，不要只停在文件列表。
- 系统建议分类/标签：展示系统给出的建议，再由用户确认。
- 元数据补全：展示标题、作者、期刊、年份、DOI、IF/JCR 等字段。
- 可问答状态：展示哪些文献已经入库，哪些还需要转换或更新索引。
- 质量/引用同步状态：短暂扫过即可，不要讲太细。

### Chat 和全库问答细节

- 范围切换：明确展示“本文 / 文献篮 / 全库”，让观众知道不是只问当前 PDF。
- 参考定位卡片：展示相关性、来源、页码/章节、DOI 或摘要。
- 非当前论文证据：点击一篇不是当前 Reader 的文献，证明全库检索真的跨文献。
- 回答继续追问：从“找相关论文”追问到“整理阅读路径”，体现研究连续性。
- 回答中的引用和证据入口：不要只拍最终文字，要拍可点击的证据。

### Reader 细节

- 侧边 Reader：从回答证据打开，展示原文定位。
- 独立 Reader：点击单独页打开，展示更完整的阅读空间。
- 文内交叉引用：点击正文里的引用标记，弹出参考文献卡片。
- Reader 选中文本：选中一段原文，加入文献篮或围绕选中文本提问。
- 证据反馈：如果页面上有“有用 / 需复核”一类反馈，可以轻轻扫过，不必展开。

### 文献篮和 Cite 细节

- 从回答加入文献篮。
- 从 Reader 原文选段加入文献篮。
- 从文内交叉引用卡片加入文献篮。
- 文献篮搜索、筛选、标签、分组。
- 保存本机快照。
- 一键导出 Cite：重点展示 BibTeX、RIS、Markdown、GB/T。
- 导出范围：展示“当前筛选 / 全部”，说明不是只能导出单条。

## 左侧栏历史会话布景

左侧栏会出现在很多镜头里，不能露出测试样例。录制前建议新建一个演示项目，例如：

> π-zaya Demo

把广告相关会话都放进这个项目，隐藏或避免露出 `research-qa-*`、`__test__`、`weak-system-*`、`required-fallback-*`、`manual-regression`、`debug`、`tmp` 这类测试会话。

### 建议展示的真实端到端会话名

这些标题看起来像真实研究流程，也能对应广告镜头：

- 全库检索：单光子成像的噪声建模
- 阅读指导：Physics-informed single-photon imaging
- Reader 核查：原文证据与交叉引用
- 阅读路径：计算成像与物理先验
- 文献篮整理：related work 候选文献
- 引用导出：BibTeX / RIS / Markdown

### 侧栏拍摄建议

- 侧栏展开时只展示演示项目和少量真实会话。
- 会话标题要短、专业、像研究任务，不要像测试用例。
- 可以保留 5-6 个会话，太多会显得杂乱。
- 如果需要展示“很多历史”，也应该是研究主题名，而不是代码测试名。
- 正式录屏前先打开目标演示项目，让侧栏停在干净状态。

### 可选会话顺序

建议把会话顺序排成一个研究流程：

1. 全库检索：单光子成像的噪声建模
2. 阅读指导：Physics-informed single-photon imaging
3. Reader 核查：原文证据与交叉引用
4. 阅读路径：计算成像与物理先验
5. 文献篮整理：related work 候选文献
6. 引用导出：BibTeX / RIS / Markdown

## 关键提问清单

广告里的问题要短、真实、稳定。不要把太多要求塞进一个问题，否则回答容易变长、变散，也不利于剪辑。

提问原则：

- 第一问一定是全库问题，突出主功能。
- 录制时在界面上选择“全库”，不要在问题里生硬写“从整个文献库里找”。
- 问题要像研究者真实会问的，不要像测试脚本。
- 每个问题只承担一个镜头目标。
- 需要控制长度时用“列出几种代表性做法 / 分 3 点 / 每点一句依据”，避免回答太长。
- “原文依据”比“source”更适合中文广告。

### 普通模式全库问题

```text
单光子成像为什么需要专门建模噪声？有哪些代表性做法？
```

### 从参考定位进入阅读指导后

```text
这篇论文为什么和刚才的问题相关？请用 3 点说明，并给出对应的原文依据。
```

### 文内参考追踪

```text
这篇论文里哪些正文引用和噪声建模有关？请帮我定位到引用位置和参考文献条目。
```

### 阅读路径整理

```text
把刚才找到的论文整理成一个阅读路径：先读哪篇、再读哪篇，每篇重点看什么？
```

### 写作准备

```text
把文献篮里的内容整理成 related work 写作提纲，每条观点保留对应引用。
```

## 导演备注

广告不要拍成“功能菜单巡礼”。每个功能都要放进同一个故事：

> 我有一批 PDF。  
> 我想把它们整理成文献库。  
> 我先问一个全库问题。  
> π-zaya 从整个库里找到相关文献和证据。  
> 我从参考定位进入关键论文的阅读指导。  
> 我回到原文核查证据。  
> 我继续追踪论文内部引用。  
> 我把重要线索放进文献篮。  
> 我一键导出 Cite，继续写作。

只要这条故事线不断，功能再多也不会散。
