### 本版重点

- 转换质量门禁继续默认阻止存在关键缺陷的文献入库。
- 当诊断能够定位到具体问题页时，文献库会显示对应页码，并只重转这些页面；
  其余页面继续复用已验证的分页缓存。
- 定向修复开始前会保留原 Markdown、图片和分页缓存。新结果只有在质量门禁通过、
  目标页均恢复可靠且没有新增阻断问题时才会被采用，否则自动恢复原结果。
- 如果重新转换后仍命中较保守的质量规则，用户可以先对照 PDF 检查当前
  Markdown，再通过“确认当前 Markdown 入库”执行一次全新的质量扫描。
- 如果重新扫描通过，文献正常入库；如果仍命中规则，文献会带质量警告入库，
  原阻断原因和用户确认记录都会保留，避免问题被静默隐藏。
- 已检测为不可靠的页面仍不会成为回答证据，文档级确认不会降低页面级证据
  安全边界。
- 证据矩阵及其依赖入口继续不向普通用户展示；文献库、PDF 转 Markdown、
  文库问答、引用定位、文内参考卡片和研究摘录篮继续正常提供。

### 校验和与签名边界

- 每个正式构建都必须同时提供 Setup、便携 ZIP、对应的 SHA-256 文件和两份
  manifest；相邻的校验文件是下载完整性校验依据。
- manifest 会记录准确的发布提交、`source_dirty=false`、MIT 许可证、嵌入式
  Python 运行时以及真实签名状态。
- 只有 manifest 记录 `signed: true` 且 Windows 验证受信任发布者时，构建才
  能称为已签名；否则该公测版会明确标记为未签名。

## English download guide

This beta patch adds a controlled recovery path for conservative conversion
quality blocks. Most Windows users should download Setup; choose the portable
ZIP for no-install use, removable folders, or troubleshooting.

| File | Intended user | How to use it |
|---|---|---|
| `Pi_zaya-v0.1.0-beta.12-windows-x64-setup.exe` | Recommended for most Windows users | Verify it against `setup.exe.sha256`, run Setup, then launch Pi_zaya from the Start menu or optional desktop shortcut. It needs no administrator rights, system Python, or Node.js. |
| `Pi_zaya-v0.1.0-beta.12-windows-x64.zip` | Portable use or troubleshooting | Verify it against `.zip.sha256`, extract the entire archive to a normal folder, and double-click `Pi_zaya.exe`. |
| `*.sha256` | Anyone checking download integrity | A text checksum file, not an application. Compare it with `Get-FileHash <file> -Algorithm SHA256`. |
| `*.manifest.json` | Auditors and advanced users | Machine-readable version, commit, license, package type, and signing provenance. It is not an application. |
| GitHub-generated source archives | Developers building from source | These are not ready-to-run Windows packages. Use Setup or the portable ZIP for normal use. |

Both application packages include the Chinese guide, an embedded Python
runtime, and the prebuilt React frontend. User data defaults to
`%LOCALAPPDATA%\Pi_zaya` and survives in-place installation, uninstall, and
portable-folder replacement.

### Highlights

- The strict conversion-quality gate remains the default and still blocks
  documents with unresolved critical defects.
- When diagnostics identify specific affected pages, the library shows their
  page numbers and reconverts only those pages while reusing validated cache
  entries for healthy pages.
- Before a targeted repair, Pi_zaya preserves the existing Markdown, assets,
  and page cache. The new output is accepted only after the fresh gate passes,
  every requested page is reliable, and no new blocker appears; otherwise the
  previous output is restored automatically.
- After repeated reconversion, a user who has compared the current Markdown
  with the PDF can explicitly request a fresh scan and confirm indexing.
- A clean fresh scan produces a normal index. If the conservative rule still
  triggers, the document is indexed with quality warnings while its blocking
  codes and confirmation audit remain visible.
- Detected unreliable pages remain excluded from answer evidence after a
  document-level confirmation.
- The evidence-matrix workspace and its dependent entrances remain withheld
  from ordinary builds. The library, PDF-to-Markdown conversion, grounded Q&A,
  citation locating, in-paper reference cards, and literature basket remain
  available.

### Integrity and signing boundary

- Every formal build must provide Setup, the portable ZIP, their adjacent
  SHA-256 files, and two manifests. The adjacent checksum files are the
  authoritative download-integrity records.
- The manifests record the exact release commit, `source_dirty=false`, the MIT
  license, embedded Python runtime, and observed signing state.
- A build is signed only when its manifest records `signed: true` and Windows
  validates the trusted publisher; otherwise this beta is explicitly unsigned.
