# 本地混合检索交付验收（2026-10-13）

这次补齐的是用户可实际启用的 Windows 本地语义组件，不只是候选召回内核或
检索模式开关。beta.14 仍是未发布的本地候选；公开 beta.13 没有这些新增能力。
之前约 91 MiB 的 beta.14 便携候选没有组件清单和组件压缩包，其验收记录继续保留在
[上一轮记录](PROJECT_OPTIMIZATION_ACCEPTANCE_20261013.md)，不能算本次混合检索交付。

## 用户路径与能力边界

便携包附带经过独立验证的 multilingual-e5-small ONNX 组件。用户在聊天检索选项中
选择“启用本地语义检索”，阅读披露并确认“安装并启用”。应用复制包内压缩包，
校验长度和 SHA-256，校验解压后的文件集合，运行健康检查，再构建本地 embedding 索引。
索引就绪后才可选择混合检索。首次启动不会自动安装或启用。

包内组件安装不需下载，文献内容不为检索上传。回答生成仍调用已配置的模型 API。
组件压缩包 299,558,739 字节（约 286 MiB），安装文件 538,888,249 字节（约 514 MiB），
另需临时安装、索引与缓存空间。组件不包含个人文库；可取消、恢复或移除。

BM25 保持默认和全库路径。混合检索仅用于“本文”及已选“文献篮”，在用户来源范围内
执行 dense top K，再与 BM25 融合。明确的章节、精确引用等专用路径可保留原通道；
组件未就绪或运行失败时保留 BM25。这不是全库默认混合检索。

## 这次发现并修复的问题

- 文献篮 API 清洗丢失完整论文匹配字段和结构定位字段，导致选中文献无法正确进入
  来源约束。保留有长度限制的匹配路径、匹配状态、章节、块与锚点字段，并用真实
  后端来源过滤测试覆盖完整论文和局部摘录。
- 通用英文“each method”误触发 Methods 章节硬限制，漏掉成像论文的 Encoding
  机制。现在只有明确的章节请求才限制范围；问题点名的子章节正文有软优先级。
- 文献篮来源扫描使用已有查询扩展中的检索意图，避免只扫描宽泛的原始提问。
  用户问题、冻结验收问题和已复制的摘录不被改写。
- 包内压缩包复用既有取消、恢复、大小与 hash 校验流程；不绕过组件生命周期。
  构建清单区分组件清单与组件压缩包是否附带，干净启动验收检查组件仍未安装。
