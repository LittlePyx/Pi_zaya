只处理 `kb_chat`，延续[直接训练证据与阅读状态](DIRECT_TRAINING_EVIDENCE_20261016.md)。
main 基线为 `dd6287cf`（PR #16），合并后的 CI `38893603945` 全部通过。

`pair-n2v-n2s-noise` 和局部混合的 `pair-n2n-n2v-quality`；原 JSON、截图及错误不覆盖。

本轮先使用原生产前端和原保存回答，对上述三题及 `dncnn-output` 各测三次。
12 次中 11 次通过，首个 `dncnn-output` 失败，说明失败随启动状态变化。
该次会话元数据请求约 3.1 秒，之后才发起约 1.2 秒的消息请求，页面回答约在导航后
5.4 秒出现。`baseline-timing/timing.json` 同时保留请求事件、浏览器资源时序和 DOM 首次呈现。
这些计时不证明全部延迟都来自元数据，也不将原失败改记为通过。

## 修改与回归边界

`chatStore.selectConversation` 并发读取元数据与消息页，避免消息请求等待元数据完成。
已有论文导读缓存时继续显式使用渲染包；无缓存时由 API 按数据库中保存的会话模式选择，
不强制把普通会话当成论文导读。原 API 已支持此默认行为，本轮不修改后端。
两项新增浏览器回归将元数据请求保持未完成，要求普通会话和论文导读都能先发出消息请求。
它们在旧代码上均失败，修复后均通过；原缺失会话、非法 ID、历史窗口外会话回归继续保留。

仅并发取数的 r54 全量仍为冷启动 33/48；原内容和原阅读器各 48/48，失败原样保留在
`r54-frozen-replay/`。r55 的请求时序进一步显示：消息请求已开始时，设置响应才完成，
首次设置加载又触发相同会话的第二次消息请求，两个请求同时执行来源覆盖校验；
导航后，旧页的失败请求还可能触发兼容回退。`r55-timing/` 保留六次诊断及完整请求时序，
当时另有本地后端回归运行，因此其耗时不作为独立的性能验收。

最终 r56 使用 `useConversationLocaleRefresh` 区分首次设置加载与后续偏好变化。
首次加载只记录已保存的语言偏好，原消息 API 本就使用服务端偏好；用户实际改变语言时
仍刷新。若实际变化发生在冷会话加载期间，则等该次加载完成再刷新，防止并行重复校验。
第三项新增回归在旧前端上明确观察到两次请求；修复后首次只有一次，真正切换语言后
再有一次刷新。原加载失败、404、过期响应和语言变化处理仍按原合同检查。

后端热点实验单独保留在 `.tmp/r55p`、`r55-source-manifest.json`、补丁、探针和日志中。
36,593 个逐句探针/源块对照和 184 个完整段落选块对照均无结果差异，但只获得有限计算收益，
没有以它们宣称冷启动通过。最终源码撤回这些后端实验，仍与 main 的 307 个后端文件一致；
实验期间的 6009 项后端结果不代替最终实际提交的 CI。本轮不改变来源支撑评分或阈值。

保留原分页兼容回退、会话切换令牌、迟到响应检查、引用加载和来源支撑门。
不延长原 5000ms 检查，不更改原 24 题、期望词组、原阅读器脚本及其 30 秒进程上限。
隔离数据继续使用冻结 r48 测试库；最终生产快照为 `.tmp/r56p`，不覆盖各中间轮代码与产物。
新产物均存于 `test_results/cold_conversation_20261017/`，不访问或修改用户实际文库。

## 验收方式

本轮最终仅改会话读取前端，逐字节核验 307 个后端文件不变，并保留 359 个前端源文件、
实际使用的生产构建、组件资源、原题集和三个原验收脚本指纹。
逐一重读 r52 两模式各 24 个保存回答，要求原 content 完全一致；不重新生成或拼接答案。
对全部 48 题使用原冷启动检查和原 `_reader_checks`，分别报告性能与阅读器结果。
另重放目标卡片及 r50 原比较回答，要求实际点击、字面复制、源块、页码和返回证据均通过。

本次页面冷导航测量不代表全新安装、首次模型加载或所有机器均有相同延迟。
r52 原自动合同两模式各 24/24 和原 PDF 48/48 属于后端未变化时保留的既有证据，
不将其描述为本轮新生成的模型准确率。原全卡字面/块包含仅 47/74，另外 27 张未确认项
仍保留；本轮不修饰该审计结果，也不声称完整语义蕴含验证已实现。
