# π-zaya Take10 严格逐帧审片与重制方案

审查对象：

- `docs/ad_assets/pi_zaya_20260609/pi_zaya_ad_take10_cosyvoice_effects_11min_1280x800_h264_20260610.mp4`
- `docs/ad_assets/pi_zaya_20260609/take10_voiceover_script_zh.md`
- `docs/ad_assets/pi_zaya_20260609/create_take10_voice_assets.py`
- `docs/ad_assets/pi_zaya_20260609/take10_visual_filter.ffgraph`
- 抽帧审查目录：`docs/ad_assets/pi_zaya_20260609/take10_strict_frame_audit_20260610/`

结论：Take10 不能作为正式广告母版继续小修，必须按下面标准重录或重剪。问题不是单个镜头失误，而是录制清晰度、叠层设计、旁白脚本、字幕同步、镜头节奏同时出错。

## 1. 关键问题

### 1.1 蓝/绿/橙框线全片误导焦点

证据：

- `take10_visual_filter.ffgraph` 里使用了大面积 `drawbox`，例如 `42-93s`、`93-153s`、`178-233s`、`233-308s` 等整段框选。
- 抽帧显示框线经常框住空白、整块筛选区、整页正文或右栏整体，而不是当前点击点。

影响：

- 观众会以为框线区域是重点，但框线与旁白重点经常不一致。
- 框线遮挡 Reader 正文、公式、文献篮条目，像调试标记，不像广告引导。

解决：

- 删除全片 `drawbox` 框线。
- 只保留短暂点击光圈或鼠标点击波纹，每次 `0.4-0.8s`。
- 必要的功能强调改成小型标签，例如“入篮 +1”“定位到原文”“限定文献篮”，位置贴近按钮或状态变化，不覆盖正文。

### 1.2 清晰度不达标

证据：

- 最终视频参数：`1280x800`，H.264 视频码率约 `440 kbps`，总码率约 `588 kbps`。
- 中间视觉版也只有约 `440 kbps`；带字幕版约 `749 kbps`。

影响：

- 中文小字、英文论文标题、公式、表格线、按钮文字全部发糊。
- 这类产品广告靠界面可信度说服用户，低码率会直接降低专业感。

解决：

- 源录制使用 `1280x800` 页面视口，但浏览器缩放建议 `110%-115%`，确保文字更大。
- 录制源文件优先用高码率 WebM/MP4，不低于 `10 Mbps`。
- 最终导出建议：

```powershell
ffmpeg -i input.mp4 -c:v libx264 -preset slow -crf 16 -maxrate 16M -bufsize 32M -pix_fmt yuv420p -r 30 -c:a aac -b:a 192k output.mp4
```

- 如果后续要平台二压，母版建议保留 `CRF 14-16` 或 ProRes/H.264 高码率版本。

### 1.3 镜头停留太久，旁白和画面信息量不匹配

证据：

- 静止段检测发现至少：
  - `00:30-00:42` 约 12 秒画面变化不足。
  - `02:14-02:31` 约 16.5 秒画面变化不足。
- 逐帧接触表显示多个 30-45 秒段落停在同一页，旁白却在讲多个功能点。

影响：

- 观众会感觉“讲得很多，但画面没动”。
- 功能没有通过操作发生，只是被旁白描述。

解决：

- 正式版每 `3-6s` 必须有一个可见动作：点击、滚动、展开、计数变化、卡片打开、范围切换、导出切换。
- 单个静态镜头不得超过 `8s`，除非在展示公式/图片转换质量，并且要有慢滚动或局部放大。
- 旁白一句只对应一个画面动作，不在同一静态画面里讲 3 个以上卖点。

### 1.4 旁白混入导演指令

证据：

`create_take10_voice_assets.py` 的 `VOICE_BLOCKS` 直接包含下面这类句子，并被送入 TTS：

- “广告里这一段要建立信任感……”
- “画面中要让观众看到……”
- “回答结束后，应该稍微停留……”
- “这里还要注意单页展开形式……”
- “要展示展开的单页形式……”
- “最后的画面应该干净收束……”

影响：

- 这些不是广告内容，是给剪辑师/导演的指令。
- 用户听到后会立刻出戏，且显得视频不是正式成片。

解决：

- 旁白脚本拆成两列：`观众听到的旁白` 和 `导演执行备注`。
- TTS 只能读取 `观众听到的旁白`。
- 生成前用文本扫描拦截：旁白中不得出现 `广告里`、`画面中`、`应该`、`要展示`、`可以收起`、`这里要`、`停留`、`镜头` 这类导演词。

### 1.5 字幕与语音不严丝合缝

证据：

- TTS 文本把 `π-zaya` 读成“派 zaya”，字幕显示 `π-zaya`；这可以接受，但应统一为有意设计。
- SRT 存在硬切行导致 `Reader`、`ready` 等英文词被拆开。
- 底部黑色字幕条与画面字幕/章节条同时存在，视觉层级混乱。

影响：

- 观众会觉得“字幕和声音不是同一份稿”。
- 拆词和多层字幕降低专业度。

解决：

- 最终字幕从实际 TTS 分段生成，不再从导演稿生成。
- 每条字幕 `1.5-4s`，每行不超过 `18-22` 个汉字，最多两行。
- 英文词不拆行；`Reader`、`Markdown`、`BibTeX`、`DOI`、`π-zaya` 作为不可拆 token。
- 视频只保留一套主字幕；章节导航只做右上角短条，不与主字幕抢注意力。

### 1.6 字幕和叠层遮挡重点

证据：

- 公式段中字幕条压住底部公式/正文。
- 文献篮段字幕压住输入区和部分证据卡。
- 写作段字幕与输入框、下一轮上下文条重叠。

影响：

- 正在证明“公式可读”“证据可入篮”“范围可控制”的画面被字幕盖住。

解决：

- Reader 展示公式/图片/参考文献时，字幕移到左上或右上空白区，或短暂隐藏 `2-3s`。
- Chat 页面字幕放在回答区上方空白，不压输入框和发送按钮。
- 文献篮/导出页字幕优先放顶部，不能盖住计数、条目、导出按钮。

### 1.7 故事线仍像说明书，不像端到端研究工作流

现状：

- 有 Library、质量中心、Reader、问答、文献篮、写作，但很多功能是旁白说出来的。
- “点击后发生什么”不够清楚，功能之间的因果链弱。

应改为：

1. 我有一批 PDF，需要整理成课题文献库。
2. π-zaya 先把文献变成可检查、可检索、可问答的材料。
3. 我先用一篇高质量转换论文证明 Reader 能读公式、图片、参考文献。
4. 然后提出真实全库问题。
5. 回答给出多篇证据和引用卡。
6. 我从引用卡进入 Reader，核查原文。
7. 我把可靠文献和片段加入文献篮。
8. 我用文献篮限定范围继续提问。
9. 最后导出引用和 related work 提纲。

### 1.8 右侧栏和鼠标问题需要制作级修复

要求：

- 用页面视口录制，不录桌面小窗和系统任务栏。
- Chrome/Edge 窗口不要比录制区域大，避免用户看到右侧被裁。
- 鼠标必须来自同一个坐标系，不能后期按错误缩放叠加。

执行：

- Playwright 录制用固定 `viewport: { width: 1280, height: 800 }`。
- 如果使用真实浏览器屏幕录制，窗口外框也必须完整进入录制区域，禁止只截窗口局部。
- 鼠标点击显示采用页面内点击光圈或真实光标，不用独立坐标后期叠加。

## 2. 重制版本结构

建议长版控制在 `12-16min`。不是越长越好，而是每段必须有画面动作和信息增量。

| 段落 | 建议时长 | 必须展示 |
|---|---:|---|
| 开场定位 | 20-30s | π-zaya、文献工作流定位、不是单篇 PDF 聊天 |
| Library 文献库 | 70-90s | 多篇文献、状态、筛选、标签、质量状态 |
| 转换质量入口 | 50-70s | 质量中心、可用文献/待处理/修复入口，不展示坏 OCR 当卖点 |
| Reader 转换质量证明 | 2.5-3.5min | 从头到尾扫过一篇含公式、表格、图片、参考文献的好转换论文 |
| 全库真实提问 | 90-120s | 收起左栏，输入真实问题，生成结构化答案 |
| 引用卡与证据 | 90-120s | 展开引用卡，显示 DOI/期刊/来源/打开/入篮 |
| Reader 核查 | 90-120s | 独立单页 Reader、定位原文、高亮、章节/证据导航 |
| 文献篮组织 | 90-120s | 多篇入篮、计数变化、筛选、限定范围 |
| 写作/导出 | 60-90s | BibTeX/RIS/Markdown/GB/T，related work 提纲 |
| 收尾 | 20-30s | π-zaya 品牌和一句定位 |

## 3. 下一版硬性验收标准

- `π-zaya` 字幕和品牌全部使用希腊字符 `π`。
- 最终视频 `1280x800`，视频码率不低于 `8 Mbps`，推荐 `10-16 Mbps`。
- 不出现蓝/绿/橙大框线。
- 不出现导演指令词：`广告里`、`画面中要`、`应该停留`、`要展示`、`镜头`、`可以收起`。
- 主字幕不遮挡输入框、发送按钮、Reader 高亮、公式、图像、文献篮计数、导出按钮。
- 任意静态画面不超过 `8s`。
- 每个核心功能必须由动作证明：点击、展开、计数变化、定位、导出、范围切换。
- 右侧栏完整可见；不录系统任务栏；鼠标点击位置准确。
- 最后一遍审片必须抽帧：开头、每 10 秒接触表、每个章节关键帧、导出参数、字幕文本扫描。

## 4. 可复用与必须废弃

可复用：

- Take10 的大故事顺序：Library -> 质量 -> Reader -> 全库问答 -> 引文卡 -> 文献篮 -> 写作。
- Reader 转换质量证明这一段的方向。
- 真实问题：“为什么单光子成像需要专门建模噪声？有哪些代表性做法？”

必须废弃：

- 当前大框线视觉方案。
- 当前低码率合成链路。
- 当前 TTS 旁白稿。
- 当前底部黑字幕条位置策略。
- 当前长时间静态停留的剪辑节奏。

## 5. 推荐立即执行

1. 重写 `VOICE_BLOCKS`，只保留观众能听到的广告旁白。
2. 删除 `take10_visual_filter.ffgraph` 中全部 `drawbox`。
3. 用 1280x800 视口、110%-115% 浏览器缩放、完整右栏可见的方式重录关键操作。
4. 用高码率导出母版。
5. 抽帧和字幕扫描通过后，再做最终 TTS/字幕合成。
