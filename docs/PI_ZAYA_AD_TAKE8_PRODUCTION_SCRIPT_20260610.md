# π-zaya Take8 正式制作脚本

Date: 2026-06-10

Purpose: 把严格审查中发现的问题、需要补充的功能细节、以及新的故事线，落实成可以直接录制和剪辑的广告视频脚本。

Target length: `22-25 min`

Target canvas: `1280x800`

Entry points only:

- React app: `http://127.0.0.1:5173/`
- FastAPI backend: `http://127.0.0.1:8000/`

Do not use the removed Streamlit entry, `app.py`, `streamlit run`, or port `8501`.

## Creative Direction

Take8 的定位不是“演示一个聊天框”，而是“展示一个完整的学术文献研究工作台”。

核心故事线：

> 研究问题出现 -> PDF 入库 -> 转换质量可控 -> Library 管理 -> 全库发现证据 -> 切换范围验证 -> Reader 单页精读 -> 文献篮沉淀证据 -> 导出引用 -> 生成写作提纲。

广告必须让观众看见三件事：

1. π-zaya 能把本地 PDF 变成可维护的知识库。
2. π-zaya 的回答能回到原文、引用、Reader 和文献篮里被验证。
3. π-zaya 的终点不是“看完一个答案”，而是帮助研究者开始写作。

## Review Findings To Production Fixes

| 审查发现 | 制作落实方式 | 验收标准 |
|---|---|---|
| 入库、转换、质量修复没有充分展示 | 在前 5 分钟加入 Library、上传、转换状态、质量中心、修复建议 | 观众能明确知道 π-zaya 不是单篇 PDF 聊天工具 |
| Reader 有旧证据条、Markdown/LaTeX 残留 | 重新录 Reader，使用干净自然语言证据片段，避开图片 OCR 异常段落 | 画面里不出现大段错误转换文字、不出现旧脏证据条 |
| 字幕遮挡聊天输入框和底部控件 | 聊天页字幕底部离画面至少 `84px`；Reader 页字幕放低且短；导出页字幕移到顶部 | 输入框、发送按钮、导出按钮、文献篮计数始终可见 |
| 文献篮增长因果不清楚 | 每次加入文献篮后停 1-2 秒，让计数变化被看见 | 至少展示 4 次不同来源的加入动作 |
| 范围切换价值不够清楚 | 同一研究任务依次展示“全库、本文、文献篮”三种范围 | 旁白明确说明发现、核查、综合三阶段 |
| 缺少写作结果 | 结尾用文献篮范围生成 related work 提纲，并展示引用导出 | 故事终点从“找到资料”升级为“准备写作” |
| 右侧栏曾被截断 | 全程用 `1280x800`，文献篮不用时拖窄，需要展示时展开 | 截图和视频中右侧面板完整显示 |
| 鼠标点击位置曾偏移 | 录制前用可见鼠标指针做点击校准，避免浏览器缩放和录屏缩放不一致 | 点击落点和视觉光标一致，重要点击有短暂停顿 |
| 小窗录制导致画面糊 | 使用 1280x800 内容窗口，导出 H.264，码率不低于 8 Mbps | 字体、按钮、引用卡片在 100% 播放时清晰 |

## Pre-Recording Setup

1. 启动项目：
   - `.\run_new.ps1 -StopExisting`
   - 确认 React 在 `http://127.0.0.1:5173/`
   - 确认 FastAPI 在 `http://127.0.0.1:8000/`
2. 浏览器窗口：
   - 内容画幅 `1280x800`
   - 关闭无关浏览器标签
   - 不录 Windows 任务栏
   - 浏览器缩放保持 `100%`
   - 录制前用按钮点击做一次鼠标落点校准
3. UI 状态：
   - 聊天正式提问时收起左侧会话栏
   - 文献篮不用时拖窄，只保留入口和计数
   - 展示文献篮时展开到完整宽度，但不能遮住主答案
   - 展示 Reader 时使用单独页形式，不使用被侧栏挤压的 Reader
4. 演示数据：
   - 至少 20 篇可见文献
   - 至少 5 篇已转换可问答
   - 至少 3 个分类
   - 至少 6 个标签
   - 文献篮开场为空，录制过程中逐步加入
5. 安全检查：
   - 不显示 API key、`.env`、私人路径、私人聊天
   - 不展示大段不适合公开的论文全文
   - 避免展示转换错误严重的图片 OCR 文本
   - 品牌统一写作 `π-zaya`

## Overlay And Subtitle Rules

- 章节卡片：只在每章开始出现 `3-4s`，位置在左上角，不压住标题或回答正文。
- 流程提示条：右上角短句，进入稳定操作后淡出，不抢右侧栏标题。
- 主字幕：每句不超过 24 个汉字，停留 `2.5-4s`。
- 聊天页字幕：底部 `84px` 以上，不能遮住输入框。
- Reader 页字幕：底部 `22px` 左右，短句，不能盖住当前高亮段落。
- 文献篮/导出页字幕：优先放顶部或左侧空白区域，不能盖住导出按钮。
- 鼠标：点击前停 `0.3s`，点击后停 `0.5-1s`，让观众看懂动作结果。

## Main Narration Thread

开场旁白：

> 做科研时，真正耗时的不是问一句问题，而是整理 PDF、判断材料质量、回到原文核查证据，再把可靠文献变成可以写进论文的引用。

中段旁白：

> π-zaya 把这个过程连起来：它先管理文献库，再从全库检索证据；当你需要确认时，可以切换到单篇论文和 Reader 原文；当你准备写作时，可以只围绕文献篮里的已选资料综合。

结尾旁白：

> 这不是一个只会生成答案的聊天框，而是一个从 PDF 到证据、从证据到引用、从引用到写作提纲的研究工作台。

## Shot-By-Shot Script

### 00:00-00:08 Brand Card

画面：

- 黑底或浅底品牌卡。
- 居中显示 `π-zaya`。
- 副标题：`从 PDF 文献库提问，到可追溯研究证据。`

旁白：

> π-zaya，让本地 PDF 文献库真正可问、可查、可引用。

字幕：

> 从 PDF 文献库，到可追溯研究证据。

验收：

- `π-zaya` 使用希腊字符 `π`。
- 不出现 `Pi_zaya`、`pi-zaya` 或乱码品牌。

### 00:08-01:20 Research Problem

画面动作：

1. 打开 React 首页。
2. 展示空输入框和文献篮入口。
3. 在输入框输入但暂不发送：
   `我要写 single-photon imaging 噪声建模的 related work，需要找到代表性做法并核对原文证据。`
4. 收起左侧会话栏，文献篮保持窄状态。

旁白：

> 先把任务说清楚：我不是只想问某一篇 PDF，而是要从整个文献库里找到相关工作，核对原文依据，并准备写 related work。

字幕：

> 研究任务：发现文献、核查证据、准备写作。

验收：

- 输入框和右侧文献篮入口无遮挡。
- 鼠标点击落点准确。

### 01:20-03:30 PDF Intake And Library Readiness

画面动作：

1. 点击侧栏 Library / 文献管理。
2. 展示文献列表，快速滚动，停在状态列。
3. 展示一个新 PDF 的上传、命名建议或待处理状态。
4. 展示转换中、入库中、已就绪状态。
5. 如果真实转换耗时，剪辑时用速度 ramp，保留状态变化关键帧。

旁白：

> 研究流程从入库开始。π-zaya 会把 PDF 放进可管理的 Library，并把转换、索引和可问答状态显示出来。

字幕：

> Library：PDF 入库、转换、索引和可问答状态。

可选补拍：

- 自动命名建议。
- 重名或重复 PDF 提示。
- 引用同步状态。

验收：

- 画面能看到多篇文献，而不是单篇 PDF。
- 至少出现一次“可问答/ready/已转换”类状态。

### 03:30-05:20 Quality Center And Repair

画面动作：

1. 打开质量中心或文献质量详情。
2. 展示源质量评分、待修复项或转换风险提示。
3. 展示修复建议或修复队列。
4. 展示修复后状态，或展示“无严重问题/已完成”。

旁白：

> PDF 转 Markdown 最怕悄悄出错。π-zaya 会把转换质量暴露出来，让你知道哪些文献需要修复，哪些证据可以放心追溯。

字幕：

> 转换质量可见：发现问题、计划修复、保留追溯。

注意：

- 不要停留在图片 OCR 失败的杂乱文字上。
- 如必须说明转换风险，用短字幕解释“这是系统识别出的待修复内容”，不要把坏内容当作卖点画面。

验收：

- 观众能理解这是质量控制功能，而不是页面错误。
- 不出现大面积脏 OCR 文本作为主要画面。

### 05:20-06:40 Library Organization

画面动作：

1. 在 Library 搜索 `single-photon` 或 `SPAD`。
2. 展示分类、标签、阅读状态、备注。
3. 点开一篇文献元数据。
4. 修改或展示分类/标签。
5. 可展示批量分类、标签筛选或引用同步状态。

旁白：

> 文献库不是静态列表。分类、标签、备注和同步状态会让之后的检索更像研究项目，而不是临时聊天。

字幕：

> 分类、标签、备注和引用同步，让文献库可维护。

验收：

- 至少展示 3 个标签或分类。
- 不暴露私人路径。

### 06:40-08:40 Full-Library Question

画面动作：

1. 回到聊天页。
2. 确认范围为“全库”。
3. 发送问题：
   `单光子成像为什么需要专门建模噪声？有哪些代表性做法？`
4. 等待检索和生成。
5. 展示回答结构：原因、噪声类型、代表做法、局限、下一步建议。

旁白：

> 现在进入全库提问。它先从整个知识库里找到候选证据，再把答案组织成可以继续追查的结构。

字幕：

> 全库范围：先发现候选证据。

验收：

- 左侧栏收起，主回答清晰。
- 字幕不遮住输入框。
- 回答中至少可见 2 个引用标记或参考入口。

### 08:40-10:20 Evidence And Reference Cards

画面动作：

1. 点击回答中的参考或引用卡片。
2. 展开参考卡详情。
3. 展示 DOI、年份、期刊、IF/JCR、证据焦点、原文证据。
4. 复制 BibTeX 或 GB/T。
5. 将 1-2 篇加入文献篮，停顿展示计数变化。

旁白：

> 这里的引用不是装饰。每个参考可以展开，看它为什么被引用、证据来自哪里，以及能不能直接用于写作引用。

字幕：

> 引用卡片：来源、证据、元数据和引用格式。

验收：

- 文献篮计数变化清楚可见。
- 不让字幕遮住“加入文献篮”按钮。

### 10:20-12:20 Scope Switch

画面动作：

1. 展示范围控件。
2. 保持同一主题，依次切换：
   - 全库：发现候选文献。
   - 本文：核查当前论文。
   - 文献篮：只综合已选文献。
3. 每个范围发一个短问题：
   - 全库：`哪些论文讨论了 SPAD 噪声建模？`
   - 本文：`这篇论文具体如何处理 shot noise？`
   - 文献篮：`只基于文献篮，概括这些方法的共同点。`

旁白：

> 范围切换是研究节奏：全库负责发现，本文负责核查，文献篮负责把已经筛选过的资料综合起来。

字幕：

> 全库发现 -> 本文核查 -> 文献篮综合。

验收：

- 三次范围切换都要被看见。
- 不需要完整等待三次长回答，可剪辑保留关键回答片段。

### 12:20-15:40 Single-Page Reader Deep Use

画面动作：

1. 从引用卡片点击“打开”或“进入 Reader”。
2. 进入单独页 Reader，而不是侧边压缩 Reader。
3. 展示章节目录、证据定位、当前页上下文。
4. 展示上一条/下一条证据。
5. 选中一段自然语言文本。
6. 添加高亮。
7. 对选中文本提问：
   `这段话说明了哪一种噪声假设？`
8. 将选中文本或相关引用加入文献篮。
9. 标记证据有用或需要核查。

旁白：

> 生成答案之后，最关键的是回到原文。Reader 的目标不是再开一个 PDF，而是让你围绕证据继续阅读、标记、提问和收集。

字幕：

> Reader 单页：定位证据、阅读上下文、选择文本继续追问。

禁止画面：

- 不展示图片 OCR 被错误转成大段文字的段落。
- 不展示旧的 LaTeX/Markdown 残留证据条。

验收：

- Reader 页面完整显示，右侧栏不被裁切。
- 当前段落、证据标签和鼠标指针不被字幕遮挡。
- 至少一次选中文本和一次高亮动作清楚可见。

### 15:40-18:40 Literature Basket

画面动作：

1. 回到聊天页，展开文献篮。
2. 展示文献篮里来自不同来源的条目：
   - 回答引用。
   - Reader 引用。
   - Reader 选中文本。
   - 参考文献表。
3. 展开一条详情。
4. 添加或展示标签。
5. 按标签筛选或分组。
6. 批量选择 3 篇。
7. 保存快照。
8. 删除一条，再从快照恢复。

旁白：

> 文献篮不是收藏夹，而是写作前的证据暂存区。你可以从回答、原文和参考表里收集材料，再按主题整理。

字幕：

> 文献篮：把证据变成可整理、可导出的研究材料。

验收：

- 至少 4 条文献篮来源被展示。
- 计数变化、标签、快照至少各出现一次。
- 展开文献篮时主内容仍能看懂。

### 18:40-20:20 Export And Metadata Preflight

画面动作：

1. 在文献篮中点击导出。
2. 展示导出范围：当前选中、当前筛选、全部。
3. 展示格式：BibTeX、RIS、Markdown、GB/T、CSV。
4. 展示元数据预检或缺失提醒。
5. 复制或导出一次。

旁白：

> 当材料准备好之后，π-zaya 可以把文献篮直接变成引用格式和写作材料。缺失的元数据也应该在导出前被发现。

字幕：

> 导出前预检：范围、格式、元数据。

验收：

- 导出按钮和格式选择不被字幕遮住。
- 至少展示一种中文引用格式或 GB/T。

### 20:20-21:40 Writing-Ready Output

画面动作：

1. 回到聊天页。
2. 切换范围到“文献篮”。
3. 输入：
   `根据文献篮中已选文献，生成 related work 小节提纲，并标注每一点对应引用。`
4. 展示生成结果：
   - 主题层级。
   - 每一点对应引用。
   - 可继续核查的来源。

旁白：

> 这一步把前面的所有动作收束起来：我们不是只得到几条答案，而是得到一个能继续写作和核查的 related work 提纲。

字幕：

> 从已选证据，到可写作的 related work 提纲。

验收：

- 结果中能看到提纲结构和引用标记。
- 文献篮范围状态清楚可见。

### 21:40-22:40 Trust And Operations

画面动作：

1. 快速蒙太奇展示设置或系统状态。
2. 展示模型/API 连接状态，如可见。
3. 展示备份、诊断导出或恢复演练，如可见。
4. 展示后台任务或队列状态。

旁白：

> 对一个本地研究系统来说，稳定性同样重要。备份、诊断和任务状态让这个工具更适合长期使用。

字幕：

> 本地研究工作台，也需要可维护和可诊断。

验收：

- 每个镜头 2-4 秒即可，不拖慢主线。
- 没有隐私路径或密钥。

### 22:40-23:00 Ending Card

画面：

- 回到干净品牌卡。
- 标题：`π-zaya`
- 副标题：`让你的 PDF 文献库真正可问、可查、可引用。`

旁白：

> π-zaya，让文献库成为你的研究证据系统。

字幕：

> 可问。可查。可引用。

验收：

- 品牌写法正确。
- 结尾不超过 20 秒，干净收束。

## Retake Priority List

如果时间有限，优先补拍以下镜头：

1. Reader 单独页完整流程：定位、选中文本、高亮、追问、加入文献篮。
2. Library 入库和质量中心：证明系统不只是聊天 UI。
3. 范围切换三连：全库、本文、文献篮。
4. 文献篮高级流程：多来源加入、标签、快照、导出。
5. 写作提纲输出：把广告结尾落在研究成果上。

- 右侧栏完整显示，不裁切。
- 鼠标可见，点击位置准确。
- 不出现脏 OCR 文本作为卖点画面。
- `π-zaya` 品牌全片一致。

## Final Acceptance Standard

Take8 只有在满足以下标准时才算通过：

- 一个从未见过项目的人，看完能说出 π-zaya 的完整工作流。
- 一个研究生，看完能知道它如何节省查文献、核证据、整理引用的时间。
- 一个严格审查者，看不出明显遮挡、裁切、鼠标错位、字幕压控件或脏转换内容。
- 一个潜在用户，会记住这不是 PDF chatbot，而是本地学术文献研究工作台。
