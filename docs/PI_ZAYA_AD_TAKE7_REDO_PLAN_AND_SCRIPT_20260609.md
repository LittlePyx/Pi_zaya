## 严格结论

如果按公开视频广告标准，当前 trimmed take6 不建议直接发布。它已经解决了黑帧、右侧栏截断、Reader 单页展示、文献篮数量和结尾空白问题，但仍然更像“录屏底稿”，不是完整成片。

建议重录 take7，而不是只在 take6 上修字幕。take6 可以保留为节奏参考和备份素材。

## 当前 take6 的主要问题

1. 开场鼠标太显眼。品牌卡首帧右下角有大鼠标，广告第一印象不够干净。
2. “真实端到端提问”还不够硬。take6 有输入问题镜头，但更像演示预置流程；take7 必须展示输入、发送、检索、生成、答案出现的连续变化。
3. 章节导航存在，但广告感还不够强。需要统一的章节条、进度条和底部字幕，而不是只靠画面动作让观众理解。
4. Reader 段仍有风险。必须只用干净段落、章节导航、文内引用卡，不要扫到图内 OCR 残留文字。
5. 文献库质量中心展示偏轻。现在能看到文献管理，但“转换质量、待处理、修复推荐、标签分类”没有形成明确卖点。
6. 文献篮展示要更有因果。不能突然出现 6 篇，要明确展示“从回答入篮、从 Reader 引用入篮、再筛选/导出”。
7. 画面仍需要广告包装。没有旁白、字幕、章节导航时，非熟悉项目的人会漏掉产品价值。

## 重录策略

高标准方案：重录 take7，控制在 `14:50-15:20`。不要追求功能越多越好，要追求每个功能都服务同一条研究流程。

保留 take6 中可复用的设计：

- `1280x800` 画幅。
- 单页 Reader，而不是右侧抽屉 Reader。
- 6 篇文献篮与多格式导出。
- 品牌收束卡。
- 裁掉开头过渡帧的 ffmpeg 流程。

take7 必须重录或补录的镜头：

- 开场品牌卡：隐藏鼠标或放到画面边缘外。
- 全库提问：真实输入、发送、检索、生成、答案出现。
- 文献篮：至少展示 3 次来源不同的入篮动作。
- 文献管理：补一个质量中心近景，停在“文库维护 / 待处理 / 修复推荐 / 标签分类”。
- Reader：只停在干净段落、章节导航、文内引用卡，不扫坏转换区域。

## 文字导航规范

导航 overlay 建议三层，所有字幕后期统一叠加，不依赖页面自身文字。

1. 顶部章节条

位置：左上角，距离画面边缘 `32px`。

格式：
```text
01 文献库准备
```

2. 顶部流程条

位置：右上角。

格式：
```text
问 -> 查 -> 读 -> 收集 -> 导出
```

当前阶段加粗或高亮，不要每一步都同时抢眼。

3. 底部字幕

位置：底部居中，避开输入框和右侧文献篮。聊天页时可上移到输入框上方，Reader 页固定在底部安全区。

规则：

- 每屏最多 2 行。
- 每行最多 22 个中文字符。
- 不遮挡按钮、输入框、文献标题、DOI。
- 字幕只解释“为什么看这个画面”，不重复读按钮名。

## 一票否决项

出现以下任一项，镜头必须重录或剪掉：

- 右侧栏或页面主体被录屏边界截断。
- 鼠标点击光圈和实际点击位置明显错位。
- 桌面任务栏、非浏览器窗口、调试终端进入画面。
- Reader 中暴露明显图内 OCR 残留文字。
- 页面空白、加载中、跳转中停留超过 1 秒。
- 字体小到 1280x800 下无法读清主要卖点。
- 开场或结尾出现黑帧、白屏、半渲染标题卡。
- 文献篮条目突然增加，但没有前置入篮动作。
- 旁白说的功能和画面显示的功能不同步。
- 使用旧 Streamlit 入口、`app.py`、`streamlit run` 或 `8501`。

## 15 分钟 take7 分镜脚本

### 00:00-00:15 品牌开场

画面：

- 稳定品牌卡。
- 鼠标隐藏或放到右下角安全区外，不遮挡品牌文字。

顶部章节：
```text
00 开场
```

流程条：
```text
问 -> 查 -> 读 -> 收集 -> 导出
```

底部字幕：
```text
从 PDF 文献库提问，
到可追溯研究证据。
```

旁白：
> 做文献调研时，真正耗时间的不是得到一句答案，而是确认这句答案从哪里来。

### 00:15-01:30 文献库准备

画面：

- 打开文献管理。
- 展示 21 篇文献、已转换、可问答、质量状态。
- 鼠标扫过质量分、标签、分类、待处理。
- 停在“文库维护 / 处理 1 篇重点文献 / 修复推荐”区域 6 秒。

顶部章节：
```text
01 文献库准备
```

底部字幕：
```text
先确认文献库本身可靠，
再让系统回答问题。
```

旁白：
> Pi_zaya 不是从一个空聊天框开始。它先把 PDF 转换、分块、索引，并记录哪些文献已经可以问答，哪些还需要维护。

严格要求：

- 这一段必须让观众看到“不是空 demo”。
- 不要只扫文件列表，必须停在质量中心或维护区。

### 01:30-02:15 进入真实问题

画面：

- 回到聊天页。
- 收起左侧栏。
- 文献篮不展示或拖窄，只保留内容主画面。
- 光标进入输入框。

顶部章节：
```text
02 全库提问
```

底部字幕：
```text
这次不是问单篇 PDF，
而是问整个文献库。
```

旁白：
> 接下来问一个真实研究问题。不是“总结这篇论文”，而是让系统跨文献库找证据。

正式问题：
```text
单光子成像为什么需要专门建模噪声？有哪些代表性做法？
```

### 02:15-03:20 端到端发送与生成

画面：

- 实时输入正式问题。
- 选择“全库”。
- 点击发送。
- 展示检索、生成、答案逐步出现。

顶部章节：
```text
02 全库提问
```

底部字幕：
```text
输入问题，检索文献，
再生成可核查回答。
```

旁白：
> 这里要保留完整过程：输入问题、选择全库、发送，然后看到系统检索相关论文片段并生成回答。

严格要求：

- 不要直接跳到已有答案。
- 如果生成等待太久，可剪快，但必须保留“正在检索/生成”的变化。

### 03:20-04:30 结构化回答

画面：

- 停在回答主体。
- 鼠标依次扫过“噪声来源、代表性做法、局限性、下一步建议”。
- 不要滚动太快。

顶部章节：
```text
03 结构化回答
```

底部字幕：
```text
回答按研究结构展开：
原因、方法、局限和下一步。
```

旁白：
> 一个可用的研究回答，不应该只给一句结论。它要把原因、方法、局限和下一步拆开，并且能继续追到来源。

### 04:30-05:45 参考定位与第一批入篮

画面：

- 展开参考定位。
- 停在命中的文献卡。
- 展示标题、DOI、IF/JCR、打开、入篮。
- 点击 1-2 篇“入篮”，显示反馈。

顶部章节：
```text
04 参考定位
```

底部字幕：
```text
答案下方直接接文献来源，
不是孤立文本。
```

旁白：
> 到这里不要急着相信答案。先看相关文献卡：标题、来源、DOI、期刊指标和操作入口都在同一处。

严格要求：

- 文献卡信息必须可读。
- 入篮动作要真实发生，不能后面突然多出文献。

### 05:45-06:45 进入单篇阅读指导

画面：

- 点击相关论文的阅读入口。
- 进入阅读指导会话。
- 展示“本文 / 全库”范围控制。
- 输入追问。

顶部章节：
```text
05 单篇精读
```

底部字幕：
```text
全库找线索，
本文做精读。
```

追问：
```text
这篇论文为什么和刚才的问题相关？请用 3 点说明，并给出对应的原文依据。
```

旁白：
> 全库适合发现线索，本文适合确认线索。现在围绕刚才命中的论文继续追问，要求系统给出原文依据。

### 06:45-08:20 单页 Reader 核查

画面：

- 从回答点击“原文”。
- 切到独立单页 Reader。
- 停在干净段落。
- 展示“当前核对”蓝色证据条。
- 点击“章节”，展示章节导航。
- 点击“证据”，回到高亮段落。

顶部章节：
```text
06 Reader 核查
```

底部字幕：
```text
每个关键结论，
都能回到原文位置。
```

旁白：
> Reader 是这条广告里最重要的可信度镜头。它让答案回到原文结构里，而不是停留在生成文本里。

严格要求：

- 只用干净段落。
- 不滚到 Figure 7 或图内 OCR 残留区域。
- Reader 必须是单页展开形式。

### 08:20-09:35 文内引用卡

画面：

- 在 Reader 正文中点击 `[38]` 或 `[39]`。
- 弹出文内引用卡。
- 展示 DOI、被引、IF、JCR、摘要。
- 点击“加入研究摘录篮”。

顶部章节：
```text
07 文内引用
```

底部字幕：
```text
读到正文引用，
也能继续追踪和收藏。
```

旁白：
> 精读时遇到正文引用，也可以继续展开成文献卡。related work 不是事后从零整理，而是在阅读过程中自然沉淀。

### 09:35-10:50 研究摘录篮

画面：

- 回到聊天页。
- 打开研究摘录篮。
- 展示 4-6 篇文献。
- 展开一条详情，显示摘要、来源、DOI。
- 再展开另一条，证明不是静态列表。

顶部章节：
```text
08 研究摘录篮
```

底部字幕：
```text
把问答、精读和引用线索
沉淀成 related work 候选。
```

旁白：
> 研究摘录篮不是普通收藏夹。它把回答里发现的论文、Reader 里追到的引用、以及后续写作需要的候选文献放到一起。

严格要求：

- 至少显示一次展开详情。
- DOI 或来源信息要可见。

### 10:50-12:05 筛选、选择、保存快照

画面：

- 使用搜索或筛选。
- 勾选 2-3 篇。
- 切换范围：当前筛选、选中、全部。
- 点击保存本机快照。

顶部章节：
```text
08 研究摘录篮
```

底部字幕：
```text
不是只收藏，
还要筛选、选择和保存。
```

旁白：
> 当候选文献变多时，篮子还要能筛选、选择、保存快照。这样它才像一个写作前的研究工作台。

### 12:05-13:25 引用导出

画面：

- 点击导出引用。
- 展示 BibTeX / RIS / Markdown / GB/T / CSV。
- 切换选中、当前可见、全部。
- 停在复制 BibTeX 或下载按钮。

顶部章节：
```text
09 引用导出
```

底部字幕：
```text
按写作场景，
导出不同引用格式。
```

旁白：
> 最后一步是写作准备。候选文献可以按选中、当前可见或全部导出，格式包括 BibTeX、RIS、Markdown、GB/T 和 CSV。

严格要求：

- 导出格式必须全部看清。
- 不要让右栏被截断。

### 13:25-14:25 回到文献管理闭环

画面：

- 回到文献管理。
- 停在文库维护区域。
- 再扫过分类、标签、可问答状态。

顶部章节：
```text
10 完整闭环
```

底部字幕：
```text
问答结束后，
文献库仍然可维护。
```

旁白：
> 这条流程最后回到文献管理。好的学术工具不只是回答一次问题，而是让文献库长期可维护、可检索、可引用。

### 14:25-15:00 品牌收束

画面：

- 品牌收束卡。
- 背后轻微透出文献管理页面。
- 鼠标不遮挡文字。

顶部章节：
```text
Pi_zaya
```

底部字幕：
```text
让你的 PDF 文献库
真正可问、可查、可引用。
```

旁白：
> Pi_zaya，让你的 PDF 文献库真正可问、可查、可引用。

## 成片验收标准

高标准成片必须同时满足：

- 只看无声画面，也能理解流程是“问 -> 查 -> 读 -> 收集 -> 导出”。
- 只听旁白，也能理解 Pi_zaya 不是普通 PDF 聊天工具。
- 任意 30 秒内至少有一次画面状态变化。
- 每个核心功能都有一个清楚的鼠标动作证明它真的可用。
- 每个卖点都有一个可读的画面证据。
- 结尾停留在品牌卡至少 5 秒。
